# P2.5 — storage limits, low disk, idle cost — 2026-11-24

Branch `p2-limits`.

## What the hub does now

| Situation | Behavior |
|---|---|
| Free disk where the memory lives drops below `LEGENDARY_MEMORY_MIN_FREE_MB` (default 256) | Saves pause with how much is free and why; nothing is written |
| Optional allowance `LEGENDARY_MEMORY_QUOTA_MB` (local) / `QUOTA_MB` (hub) reaches 80% | Saves succeed with a note "Memory is at N% of its X MB allowance" |
| Allowance reached | New saves refused ("Memory is full: …"), importer API answers 507; the message says how to make room |
| Any of the above | **Reading, searching, exporting and deleting always work.** Nothing is deleted or summarized automatically |
| After deleting | Freed pages count as free at once (size = pages in use, not file size), so saving resumes |

Size source: local files use SQLite page counts; the Cloudflare Worker uses D1's `meta.size_after`
(D1 blocks `PRAGMA page_count`). No allowance is set on the personal hub.

## Caches, logs, temp files

The app writes no log or cache files: only the memory database, its key/config, and backups or
archives the owner asks for. Every temporary file (backup, export, move, copy snapshots) is
removed in a `finally` block; tests check none are left behind.

## Idle cost (`serve`, empty memory, 2 vCPU Linux)

30 s idle: 5 CPU ticks (≈ 0.17% of one core), resident memory 65 MiB, 7 threads (Node's default
pool), no timers or polling. Plan threshold: under 1% idle CPU.

## Overhead of the checks

10K benchmark unchanged within noise: `search` p95 18 ms, `recall` p95 8 ms, first import 2.6 s.
